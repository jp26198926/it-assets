# Fix: Ticket Report page not loading data on first navigation

## Requirements

Data should **only** be fetched from the database when the user clicks the "Apply" button — not on page mount. The page should start empty and only show records after an explicit Apply action.

## Root Cause

Two bugs in `app/(dashboard)/ticket-report/page.tsx`:

**Bug 1 — Auto-fetch on mount + stale closure.** `fetchData` is a `useCallback` depending on `[filters]`, and a `useEffect` fires it on every `fetchData` change. This means data is fetched on mount AND on every filter change, creating race conditions with the Apply button. The Apply button receives a stale `fetchData` closure from the previous render, so it can send wrong filters.

**Bug 2 — `fetch()` instead of server actions.** The page uses `fetch("/api/ticket-report?...")` while the project uses server actions. The existing server actions in `lib/actions/ticket-report-actions.ts` are defined but never used.

## Files to modify

1. **`app/(dashboard)/ticket-report/page.tsx`** — main fix
2. **`components/reports/date-range-filter.tsx`** — fix Apply/Clear button to pass filters directly

## Implementation

### 1. Refactor `page.tsx` — fetch only on Apply click

- Remove the `useEffect` that auto-fetches on mount
- Keep `useCallback` for `fetchData` but make it accept `filters` as a parameter (not rely on stale closure)
- Use server actions (`getFilteredTickets`, `getTicketSummary`, `getTicketTotals`) instead of `fetch()`
- Add `toast` for error feedback instead of silent `catch {}`
- `loading` starts as `false` (no data yet, no loading state)

```tsx
const fetchData = useCallback(async (currentFilters: TicketReportFilters) => {
  setLoading(true);
  try {
    const [ticketData, summaryData, totalsData] = await Promise.all([
      getFilteredTickets(currentFilters),
      getTicketSummary(currentFilters),
      getTicketTotals(currentFilters),
    ]);
    setTickets(ticketData);
    setSummary(summaryData);
    setTotals(totalsData);
  } catch (error) {
    toast.error(error instanceof Error ? error.message : "Failed to load ticket report");
  } finally {
    setLoading(false);
  }
}, []);
```

- No `useEffect` for fetching — data is only loaded via the Apply button
- `DateRangeFilter` receives `onApply={(f) => fetchData(f)}` — passes filters directly

### 2. Fix `DateRangeFilter` — pass filters to onApply

Change `onApply` prop type from `() => void` to `(filters: TicketReportFilters) => void`:

**In `date-range-filter.tsx`:**
```tsx
interface DateRangeFilterProps {
  filters: TicketReportFilters;
  onFiltersChange: (filters: TicketReportFilters) => void;
  onApply: (filters: TicketReportFilters) => void;  // ← accepts filters
}

// Apply button — pass current filters:
<Button size="sm" onClick={() => onApply(filters)}>
  <Search className="size-4" />
  Apply
</Button>

// Clear button — reset then apply with defaults:
onClick={() => {
  const clearedFilters = {
    date_from: defaults.from,
    date_to: defaults.to,
  };
  onFiltersChange(clearedFilters);
  onApply(clearedFilters);  // ← apply with cleared filters
}}
```

**In `page.tsx`:**
```tsx
<DateRangeFilter
  filters={filters}
  onFiltersChange={setFilters}
  onApply={(f) => fetchData(f)}  // ← explicit filters, no stale closure
/>
```
