# Fix: MissingSchemaError for "TicketCategory" on Vercel

## Root Cause

The `ticket-report-service.ts` imports the `TicketCategory` model (line 3) but **never uses the imported variable** — it only uses the string `"TicketCategory"` in `.populate("category_id", "name")`. Next.js/Webpack **tree-shakes unused imports** during the Vercel build, removing the `TicketCategory` import entirely. When `.populate()` runs on the serverless function, Mongoose can't find a registered schema for `"TicketCategory"` and throws `MissingSchemaError`.

This is intermittent because:
- Vercel reuses serverless function instances (warm invocations keep the `global.mongooseCache` alive with all previously registered models)
- On a **cold start** (new instance, new deployment, or scale-to-zero), the model is never registered, and the error fires

The same risk exists for `Department`, `Asset`, and `User` — they happen to work because they're transitively imported by other modules (e.g., auth/session) in the same execution context.

## Fix: Central Model Registration

Create a barrel file that explicitly imports all models, and import it from `connectDB()` so every database connection guarantees all schemas are registered.

### Changes

1. **Create `lib/db/models/index.ts`** — barrel file importing all 37 model files
2. **Edit `lib/db/connection.ts`** — add `import "@/lib/db/models";` at the top to trigger registration on every `connectDB()` call

### Files

| File | Action |
|------|--------|
| `lib/db/models/index.ts` | **Create** — import all models |
| `lib/db/connection.ts` | **Edit** — add side-effect import of `@/lib/db/models` |

## Verification

1. Build: `npm run build` should succeed
2. Deploy to Vercel and hit `POST /ticket-report` — should return 200 instead of 500
3. Cold-start test: trigger a fresh serverless invocation (e.g., after a new deploy) and verify no `MissingSchemaError`
