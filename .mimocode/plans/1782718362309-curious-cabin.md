# Public Support Portal

## Overview
Create a public-facing support portal at `/support` where unauthenticated users can submit tickets and track existing ones. Two main flows: submit a ticket (no login required) and track a ticket (ticket number + email lookup).

## Architecture

### New Route Group: `(public)`
Place all public pages under `app/(public)/` with its own minimal layout (no sidebar, no auth). This keeps them outside both `(auth)` and `(dashboard)` groups.

### Pages
1. **`/support`** — Landing page with two large cards: "Submit a Ticket" and "Track Your Ticket"
2. **`/support/submit`** — Public ticket submission form
3. **`/support/track`** — Lookup page: enter ticket number + email to view ticket status

### Public API Routes (no auth)
| Route | Method | Purpose |
|---|---|---|
| `app/api/public/tickets/route.ts` | POST | Create ticket (no auth) |
| `app/api/public/tickets/select-options/route.ts` | GET | Fetch categories + departments for dropdowns |
| `app/api/public/tickets/track/route.ts` | GET | Look up ticket by ticket_no + email |
| `app/api/public/tickets/lookup-asset/route.ts` | GET | Look up asset by barcode |
| `app/api/tickets/upload/route.ts` | POST | Already public — reuse for attachments |

| Field | Required | Input Type |
|---|---|---|

**On submit**: POST to `/api/public/tickets` with all fields. On success, show a success page/dialog with the ticket number and a message that credentials have been emailed (if auto-registered).

### 4. Track Page — `app/(public)/support/track/page.tsx`
Two-field form: ticket number + email. On submit, calls `/api/public/tickets/track?ticket_no=XXX&email=YYY`. Displays:
- Ticket number, title, status (with color badge), priority, category
- Created date, last updated date
- Status history timeline (optional — fetch from status logs)

### 5. API Routes

**`app/api/public/tickets/route.ts`** — POST
- No `withPageAuth` call
- Validate required fields (name, email, title, description, category_id)
- Call existing `ticketService.createTicket(data, null)` — `created_by` will be null
- Return created ticket

**`app/api/public/tickets/select-options/route.ts`** — GET
- Return categories and departments only (no assets list, no users)
- Call `ticketService.getActiveTicketCategories()` + fetch departments directly

**`app/api/public/tickets/track/route.ts`** — GET
- Accept `ticket_no` and `email` query params
- Query: `TicketModel.findOne({ ticket_no, email })` with populated fields
- Return ticket data if found, 404 if not

**`app/api/public/tickets/lookup-asset/route.ts`** — GET
- Accept `barcode` query param
- Query: `AssetModel.findOne({ barcode })` populated with item name
- Return `{ id, barcode, itemName }` or 404

### 6. Service Addition — `lib/services/ticket-service.ts`
Add `getPublicTicketByNoAndEmail(ticketNo, email)` function:
- Queries ticket by ticket_no AND email (security: must match both)
- Populates category, department, asset
- Returns ticket or null

Add `lookupAssetByBarcode(barcode)` function:
- Queries asset by barcode field
- Returns `{ id, barcode, itemName }` or null

## Key Decisions
- **No auth needed** for any public endpoint — all public routes bypass `withPageAuth`
- **Upload route already public** — reuse `/api/tickets/upload` as-is
- **Ticket tracking requires both ticket_no AND email** — prevents unauthorized enumeration
- **Auto-user registration** still works — existing `resolveRequestorId()` handles this
- **Asset lookup by barcode** — separate lightweight endpoint, avoids exposing full asset list
- **Landing page redirects root** — `app/page.tsx` changes from `/login` to `/support`

## Fix: Empty Category/Department Dropdowns

**Root cause**: The submit page uses `Promise.all` to fetch both `/api/cloudinary/settings` (wrong URL + requires auth) and `/api/public/tickets/select-options`. When the cloudinary fetch fails, the whole Promise rejects and the select options are never set.

**File**: `app/(public)/support/submit/page.tsx`

**Fix**: Fetch select options independently from cloudinary settings. If cloudinary fails, default `maxFileSize` to 10 (already the default state value). The select options will load regardless.

Replace the `useEffect` fetch logic:
```js
useEffect(() => {
  fetch("/api/public/tickets/select-options")
    .then((r) => r.json())
    .then((res) => {
      if (res.success) setOptions(res.data);
    })
    .catch(() => toast.error("Failed to load form options"))
    .finally(() => setOptionsLoading(false));

  fetch("/api/cloudinary")
    .then((r) => r.json())
    .then((res) => {
      if (res.success) setMaxFileSize(res.data?.max_file_size || 10);
    })
    .catch(() => {});
}, []);
```
