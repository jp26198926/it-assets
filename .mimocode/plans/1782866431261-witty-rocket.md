# Plan: Integrate Application Timezone into Tickets Module

## Current State (Investigation Results)

**The timezone field exists on the Application model but is NOT used anywhere in the tickets module (or anywhere else).** All dates currently render in the browser's local timezone.

### Date touchpoints in the tickets module:

| File | What it does | Current behavior |
|------|-------------|-----------------|
| `lib/services/ticket-service.ts:627-630` | "Today" filter for default view | `new Date().setHours()` — server timezone |
| `lib/services/ticket-service.ts:682-692` | Date range filter | `new Date().setHours()` — server timezone |
| `lib/services/ticket-report-service.ts:20-29` | Report date filter | `new Date().setHours()` — server timezone |
| `components/data-table/ticket-data-table-columns.tsx:194` | Ticket list date column | `format(new Date(date), "MMM dd, yyyy")` — browser timezone |
| `components/modals/ticket-view-modal.tsx:148,160,177` | Audit dates in view modal | `format(new Date(...), "MMMM dd, yyyy")` — browser timezone |
| `app/(dashboard)/tickets/[id]/page.tsx` (8 calls) | Ticket detail page dates | `format(new Date(...), ...)` — browser timezone |

`date-fns-tz` is **not installed**.

## Implementation Plan

### Step 1: Install `date-fns-tz`
```bash
npm install date-fns-tz
```

### Step 2: Create `lib/utils/timezone.ts` — Shared timezone utility

Three exported functions:
- `formatInAppTimezone(date, formatStr, timezone?)` — wraps `formatInTimeZone` from `date-fns-tz`, falls back to UTC when no timezone set
- `startOfDayInTimezone(date, timezone?)` — returns a UTC `Date` representing midnight in the target timezone (for MongoDB `$gte`)
- `endOfDayInTimezone(date, timezone?)` — returns a UTC `Date` representing 23:59:59 in the target timezone (for MongoDB `$lte`)

### Step 3: Modify `lib/services/ticket-service.ts`

- Import `getAppSettings` from application-service and timezone utils
- In `getTickets()` (line ~620): fetch timezone via `getAppSettings()`, use `startOfDayInTimezone`/`endOfDayInTimezone` for the default view "today" filter and date range filter instead of raw `setHours()`

### Step 4: Modify `lib/services/ticket-report-service.ts`

- Accept timezone parameter in `buildDateFilter()`
- Use timezone-aware day boundaries for date range queries

### Step 5: Modify client-side display components

Each component fetches the app timezone on mount and passes it to `formatInAppTimezone()`:

- `components/data-table/ticket-data-table-columns.tsx` — 1 format call (line 194)
- `components/modals/ticket-view-modal.tsx` — 3 format calls (lines 148, 160, 177)
- `app/(dashboard)/tickets/[id]/page.tsx` — 8 format calls (lines 457, 545, 549, 562, 600, 702, 710, 900)

Note: `formatDistanceToNow` (relative time like "5 minutes ago") is timezone-agnostic and stays as-is.
