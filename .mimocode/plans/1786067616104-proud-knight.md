# Fix: MissingSchemaError for "TicketCategory" in ticket-report page

## Root Cause

`lib/services/ticket-report-service.ts` calls `.populate("category_id", "name")` (line 162) inside its `populateQuery()` helper, which resolves to Mongoose model `"TicketCategory"` via the `ref` in the Ticket schema. However, the file **never imports** the `TicketCategory` model — so on Vercel's serverless functions (where each invocation starts fresh), the model is never registered in `mongoose.models`, and Mongoose throws `MissingSchemaError`.

The same issue could also affect `Department`, `Asset`, and `User` models referenced by the other `.populate()` calls in the same helper — these likely work only because they're transitively imported by other modules in the same execution context (e.g., auth/session importing `User`). `TicketCategory` has no such transitive dependency.

## Fix

**File:** `lib/services/ticket-report-service.ts`

Add static imports for all models referenced by `.populate()` calls that are not already imported:

```ts
import { TicketCategory as TicketCategoryModel } from "@/lib/db/models/ticket-category";
import { Department as DepartmentModel } from "@/lib/db/models/department";
import { Asset as AssetModel } from "@/lib/db/models/asset";
import { User as UserModel } from "@/lib/db/models/user";
```

These imports ensure the models are registered in `mongoose.models` before `populateQuery()` runs. This follows the exact same pattern used in `lib/services/ticket-service.ts` (which already imports all four models alongside `TicketModel`).

No other files need changes — the model definitions, schema refs, and populate calls are all correct. Only the missing imports in the report service need to be added.
