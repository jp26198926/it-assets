# Fix: Asset Details not updating after editing ticket asset

## Problem
In `app/(dashboard)/tickets/[id]/page.tsx`, the `handleEditConfirm` handler (line 243) updates the ticket and re-fetches it, but never re-fetches the `assetDetails` state (serial_number, item_brand, item_model). The asset details card only updates on a full page reload because the initial fetch in `useEffect` (line 185-194) is what populates `assetDetails`.

## Fix
In `handleEditConfirm`, after the ticket is refreshed, check if `asset_id` changed. If so, re-fetch asset details using `getAssetById` and update `assetDetails` state.

### File: `app/(dashboard)/tickets/[id]/page.tsx`

In `handleEditConfirm` (line 243-271), after the ticket refresh block (line 259-260), add:

```ts
// Re-fetch asset details if asset_id changed
if (data.asset_id !== ticket.asset_id) {
  if (data.asset_id) {
    const asset = await getAssetById(data.asset_id);
    if (asset) {
      setAssetDetails({
        serial_number: asset.serial_number || null,
        item_brand: asset.item_brand || null,
        item_model: asset.item_model || null,
      });
    }
  } else {
    setAssetDetails(null);
  }
}
```

This mirrors the existing pattern in the `useEffect` at lines 185-194.

## Verification
1. Open a ticket with an asset assigned
2. Click Edit, change the Asset field to a different asset, save
3. The Asset Details card should immediately show the new asset's serial number, brand, and model without requiring a page refresh
