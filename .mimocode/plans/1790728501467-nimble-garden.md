# Seed Script for Selling the Codebase

## Goal

Buyer clones the repo, points `MONGODB_URI` at a **fresh** MongoDB, runs `npm run db:seed`, and can log in and use every CRUD page. Seed pages, permissions, roles (with permission matrices), and one default admin user. All other collections stay empty and the app must still run fine.

## Decisions (confirmed)

| Topic | Choice |
|---|---|
| Seed data source | **Hardcoded** in the script (self-contained; no live-DB dependency) |
| Admin credentials | **Env vars with defaults** — `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` |
| Roles created | **Administrator + Viewer + Technician** (exact strings the code hardcodes) |
| Other collections | Empty — safe (apps/settings auto-create defaults at runtime) |

## Files

| Action | Path | Purpose |
|---|---|---|
| **Create** | `lib/db/seed-data.ts` | Pure data: `PERMISSIONS`, `PAGES`, `ROLES` + matrices. No I/O. |
| **Rewrite** | `lib/db/seed.ts` | Orchestration: connect → permissions → pages → roles → admin user → disconnect. |
| **Edit** | `.env.example` | Document `SEED_ADMIN_*` vars. |
| Unchanged | `package.json` | `db:seed` already runs `lib/db/seed.ts` via `npx tsx --env-file=.env.local`. |

Replacing `lib/db/seed.ts` (rather than a new `scripts/seed.ts`) keeps the documented `npm run db:seed` entry point and avoids two divergent seeds. Current content of `lib/db/seed.ts` only upserts role `"Viewer"` — it will be fully superseded.

## Seed data design (`lib/db/seed-data.ts`)

### Permissions — 9 docs (upsert key = `name`)

Exact strings used across `hasPermission` / `withPageAuth` call sites:
`Access`, `View`, `Add`, `Edit`, `Delete`, `Restore`, `Export`, `Assign`, `Print`.

### Pages — 36 docs (31 route leaves + 5 sidebar parent groups)

`interface SeedPage { name; path; icon; parentName: string | null; section; order; description? }`

- `name` is the unique upsert key. `/ticket-report` **must** be named `"Ticket Reports"` so it merges with any legacy row from `scripts/seed-ticket-report-page.ts`.
- `icon` values must be keys of `lib/icon-map.ts:53-102` (all planned icons verified present).
- Parent groups use non-routable `/group/*` paths — authorization is keyed by `Page.path` (`lib/services/authorization-service.ts:43-55`), so colliding parent/child paths would merge permission entries. Parents with children render as `CollapsibleTrigger`, never a `Link` (`components/layout/app-sidebar.tsx:197-247`).
- Global sequential `order` matters: `getSidebarPages()` sorts by `{ order: 1, created_at: 1 }` and the tree is assembled client-side.

### Roles + permission matrices — 3 docs (upsert key = `name`)

| Role | Matrix | Why |
|---|---|---|
| **Administrator** | all 9 permissions × all 36 pages | Sees ALL tickets (`ticket-service.ts:707`); full CRUD. |
| **Viewer** | `Access` + `View` + `Export` × all 36 pages | Read-only. **Mandatory** — `user-service.ts:272` and `ticket-service.ts:567` throw if `"Viewer"` is missing. |
| **Technician** | all 9 on `/tickets`, `/ticket-categories`, `/ticket-report`; `Access`/`View`/`Export` on the other 33 | Assignable as ticket assignee (`ticket-service.ts:1090`), scoped ticket visibility (`:713`), full ticket operator — but no master-data admin. |

Role `permissions` is an **embedded** `{ page_id, permission_id, _id: false }` subdoc array (`lib/db/models/role.ts:16-30`). Seed computes the full pairs array and `$set`s it wholesale (deterministic + re-run-safe). Do **not** use `$addToSet` (AGENTS.md: it compares `_id` on `_id: false` subdocs).

## Orchestrator (`lib/db/seed.ts`)

Keep existing contract: `connectDB()` → work → `disconnectDB()` in `finally`; `process.exit(1)` on error. Four functions:

```
seedPermissions() → Map<name, ObjectId>
seedPages()       → Map<name, ObjectId>   // two-phase parent_id resolution
seedRoles(pageIds, permIds) → Map<name, ObjectId>
seedAdminUser(roleIds)
```

### Idempotency — upsert by unique key

| Entity | Key | On insert | On existing |
|---|---|---|---|
| Permission | `name` | full doc + `created_at` | `$set` description, `status:"Active"`, `deleted_at:null` |
| Page | `name` | full doc + `created_at` | `$set` path/icon/section/order/description, `status:"Active"`, `deleted_at:null`, `parent_id` |
| Role | `name` | full doc + `permissions[]` | `$set` description/status/`deleted_at:null` + **`permissions: <computed array>`** |
| User | `email` | names, `password_hash`, `role_id`, `status:"Active"`, `is_verified:true`, `email_verified_at` | `$set` names/role/status/verified — **`password_hash` only via `$setOnInsert`** (never clobber a changed password) |

Soft-deleted seed rows are resurrected (`status:"Active"`, `deleted_at:null`) — they are system baseline the app requires.

### Page `parent_id` — two-phase name→id map

1. Upsert ALL pages with `parent_id: null`, record `name → _id`.
2. Second pass: for each row with `parentName`, `$set` `parent_id` from the map. **Throw** on missing parent name (catches `seed-data.ts` typos).

### Admin user

```ts
const email     = process.env.SEED_ADMIN_EMAIL     || "admin@example.com";
const password  = process.env.SEED_ADMIN_PASSWORD  || "admin123";
const firstName = process.env.SEED_ADMIN_FIRST_NAME || "Admin";
const lastName  = process.env.SEED_ADMIN_LAST_NAME  || "User";
const passwordHash = await bcrypt.hash(password, 10); // matches user-service.ts:172
```

- `role_id` = Administrator role's `_id`, `status: "Active"`, `is_verified: true`, `email_verified_at: now`, `department_id: null`.
- `is_verified` + `email_verified_at` skip OTP flows.
- Login lookup is exact `findOne({ email })` (`auth-service.ts:35`) — case-sensitive, no normalization. Store email as given; log the email used at seed time (never the password).
- `.env.example` already has `USERNAME`/`PASSWORD` (zero-user fallback admin) — **separate** from `SEED_ADMIN_*`. Document both clearly.

### Start-of-seed asserts

- Page names unique, leaf page paths unique (throw on duplicates in `seed-data.ts`).
- Every `parentName` references a page in the same array.
- Every `icon` is a key of `lib/icon-map.ts`.

## Edge cases

| Case | Behavior |
|---|---|
| Empty DB | 9 permissions, 36 pages, 3 roles + matrices, 1 admin. |
| Partially seeded / re-run | Upserts fill gaps; seed-owned fields refreshed; counts unchanged. |
| `"Viewer"` already exists (old `db:seed`) | Upsert upgrades it in place with the full matrix. |
| Admin exists with different password | `password_hash` preserved (`$setOnInsert` only). |
| Missing `MONGODB_URI` | `connectDB()` throws clearly; exit 1. |
| Missing `SEED_ADMIN_*` | Defaults apply. |

## Verification (after implementation)

1. `npx tsc --noEmit` (or `npm run build`).
2. **Fresh DB**: `npm run db:seed` exits 0. Counts: `permissions`=9, `pages`=36, `roles`=3 (Administrator matrix fully populated), `users`=1 with `is_verified:true`.
3. **Idempotency**: re-run → counts unchanged, no dup-key errors, admin `password_hash` unchanged.
4. **Legacy Viewer-only DB**: Viewer upgraded in place; Administrator + Technician added.
5. **Boot + login** (`npm run dev`): admin login works; sidebar shows 4 top-level + 5 collapsible groups; all 31 CRUD pages open (empty tables); Add/Export visible.
6. **API smoke**: `GET`/`POST` e.g. `/api/uoms` as admin — `Access`/`Add` gates pass.
7. **Viewer smoke**: create a Viewer user → read-only UI (no Add/Edit/Delete).
8. **Ticket hard-deps**: creating a ticket works (needs `"Viewer"`); assign dropdown lists Administrator + Technician.

## Implementation order

1. `lib/db/seed-data.ts` — PERMISSIONS, PAGES (with `parentName`), ROLES matrices + uniqueness asserts.
2. `lib/db/seed.ts` — four seed functions + orchestration + logging.
3. `.env.example` — `SEED_ADMIN_*` comment block (keep `USERNAME`/`PASSWORD` fallback docs).
4. Run verification 1–4 against a scratch DB.

**No changes** to models, services, UI, or `package.json` scripts. No new collections.
