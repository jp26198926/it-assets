# Plan: Add App Logo & Favicon Fields to Application Settings

## Goal
Add `app_logo` and `app_favicon` URL fields so users can dynamically update the app's logo and favicon via the Application Settings page. Both fields store a URL string (same pattern as existing social/download links).

## Files to Modify

### 1. `lib/types/application.ts`
- Add `app_logo: string | null` and `app_favicon: string | null` to `Application` interface
- Add both fields as optional to `UpdateApplicationInput` interface

### 2. `lib/db/models/application.ts`
- Add `app_logo` and `app_favicon` to `IApplication` interface
- Add both fields to schema: `{ type: String, default: null }`

### 3. `lib/services/application-service.ts`
- Add both fields to `toApplication()` mapping (`d.app_logo || null`, `d.app_favicon || null`)
- Add both fields to `updateAppSettings()` with the same `if (data.field !== undefined)` + empty-string-to-null coercion pattern used by existing nullable fields

### 4. `app/(dashboard)/application/page.tsx`
- Add `app_logo` and `app_favicon` to `formData` initialization in `useEffect`
- Add a new **Branding** card section with two URL input fields (App Logo URL, Favicon URL)
- Place it as the first card in the grid (before App Info) for logical grouping

## Pattern Reference
Follows the exact same pattern as `facebook_link`, `x_link`, etc.: nullable string fields with `null` default, URL input fields in the UI.

## No Changes Needed
- `lib/actions/application-actions.ts` — already passes `UpdateApplicationInput` generically
- No validation needed beyond what exists (these are optional URL fields)

## Verification
1. Run `npm run dev` and navigate to `/application`
2. Confirm the new "Branding" card appears with App Logo URL and Favicon URL inputs
3. Enter URLs, save, and verify the values persist on reload
4. Run `npm run lint` and `npm run typecheck` to confirm no type errors
