# Fix Transfer Module Issues

## Issue 1: Show stock level in Add/Edit item modal
When selecting an item in the transfer item form modal, display the available stock at the transfer's from location.

### Files to modify:
- `components/modals/transfer-item-form-modal.tsx`
- `app/(dashboard)/transfers/[id]/page.tsx`

### Changes:

**`app/(dashboard)/transfers/[id]/page.tsx`** — Pass `fromLocationId` to modal:
- Add prop `fromLocationId={transfer?.from_location_id || ""}` to `<TransferItemFormModal>`

**`components/modals/transfer-item-form-modal.tsx`** — Add stock level display:
1. Add `fromLocationId` prop to the interface
2. Add state: `const [availableStock, setAvailableStock] = useState<number | null>(null)`
3. When `formData.item_id` changes and both `item_id` and `fromLocationId` are set, dynamically import and call `getStockLevelByItemAndLocation(itemId, fromLocationId)` to fetch available stock
4. Display the available stock below the item selector (or below the qty field) as info text: "Available stock: X"
5. Reset `availableStock` when item changes or modal opens

## Issue 2: Validate stock on save
Before submitting the transfer item, verify that the requested qty does not exceed available stock.

### File to modify:
- `components/modals/transfer-item-form-modal.tsx`

### Changes:
In the `validate()` function, add a check:
- If `availableStock !== null && formData.qty > availableStock`, add error: `"Insufficient stock. Available: {availableStock}"`
- This prevents submission when qty exceeds available stock

## Issue 3: TRANSFER enum error
The error `"TRANSFER' is not a valid enum value for path 'transaction_type'"` means the running dev server loaded the old schema before "TRANSFER" was added to the enum.

### Fix:
The `lib/db/models/stock-movement.ts` file already has `"TRANSFER"` in the enum (line 23). The user simply needs to **restart the dev server**:
1. Press `Ctrl+C` to stop the current server
2. Run `npm run dev` to restart

No code changes needed for this issue.
