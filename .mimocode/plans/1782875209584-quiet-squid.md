# Fix: Favicon Race Condition

## Problem

The custom favicon displays briefly then gets replaced by the default Next.js favicon. Two competing favicon sources cause this:

1. **`app/favicon.ico`** — the default Next.js triangle icon. Next.js App Router **automatically** serves this as `<link rel="icon" href="/favicon.ico">` in the server-rendered HTML `<head>`, before any JavaScript runs.

2. **`<DynamicFavicon />`** (`components/layout/dynamic-favicon.tsx`) — a client-side component that fetches the custom favicon URL from MongoDB via a server action, then overwrites the `<link>` tag's `href` after hydration + async DB call completes.

**Race condition**: The default favicon appears immediately (server-rendered), then the custom one replaces it after the DB round-trip. If the DB call is slow, fails, or `app_favicon` is null, the default Next.js icon persists permanently.

## Solution

Use `generateMetadata` in the root layout to set the favicon **server-side** on every request, eliminating the race condition entirely. Remove the client-side `DynamicFavicon` component.

### Files to Modify

1. **`app/layout.tsx`** — Convert static `metadata` export to `generateMetadata` async function that fetches the favicon URL server-side and sets it in `metadata.icons`
2. **`components/layout/dynamic-favicon.tsx`** — Delete this file (no longer needed)
3. **`app/favicon.ico`** — Delete or replace with a transparent/empty 1x1 ICO (so there's no default icon flash even if `app_favicon` is null)

### Changes

#### 1. `app/layout.tsx`
- Convert `export const metadata` to `export async function generateMetadata()`
- Import `getAppSettings` from application-actions (server action, callable from server)
- Query DB for `app_favicon`, set in `metadata.icons.icon` (array with `{ url, type }`)
- Keep title/description in the metadata return
- Remove `<DynamicFavicon />` from the JSX
- Remove import of DynamicFavicon

#### 2. Delete `components/layout/dynamic-favicon.tsx`

#### 3. Delete or replace `app/favicon.ico`
- Option A (recommended): Delete it. If no `app_favicon` is set in DB, no favicon link tag is generated — browser uses its own default.
- Option B: Replace with a transparent 1x1 ICO as a fallback.

## Verification

1. Start dev server: `npm run dev`
2. Clear browser cache and load the app — the custom favicon should appear immediately with no flash of the default Next.js triangle
3. Open Application Settings, remove the custom favicon, reload — should show no custom favicon (browser default) instead of the Next.js triangle
4. Upload a new favicon in Application Settings, reload — should show the new favicon immediately
