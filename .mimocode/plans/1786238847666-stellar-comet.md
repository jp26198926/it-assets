# Conversion Module Implementation Plan

## Overview
Create a full "Conversion" module following the established patterns in the codebase (adjustments module as reference). This is a ledger-type module — no action buttons (edit/delete) in the datatable. To reverse a conversion, users add a new record with negative values.

## Files to Create

### 1. Model — `lib/db/models/conversion.ts`
- Fields: code (unique, "CONV00001" pattern), dateConverted, locationId (FK→locations), fromItemId (FK→items), toItemId (FK→items), fromQty, toQty, remarks
- Extends BaseAuditSchemaDefinition (created_at, created_by, updated_at, updated_by, deleted_at, deleted_by, deleted_reason)
- Indexes: code (unique), locationId, fromItemId, toItemId, dateConverted

### 2. Types — `lib/types/conversion.ts`
- `Conversion` interface (with populated name fields)
- `CreateConversionInput` interface
- `ConversionFilters` interface (search, code, location_id, from_item_id, to_item_id, date_from, date_to)

### 3. Service — `lib/services/conversion-service.ts`
- `generateConversionCode()` — auto-increment "CONV00001" pattern
- `toConversion()` — maps populated DB doc to type
- `applyPopulates()` — populates location, fromItemId, toItemId, audit users
- `getConversions(filters?)` — list with filters, sorted by created_at desc
- `getConversionById(id)` — single lookup
- `getStockLevelForItemAndLocation(itemId, locationId)` — query stock_levels
- `createConversion(data)` — **TRANSACTIONAL**:
  1. Generate code
  2. Validate fromItem has enough stock at location (throw if insufficient)
  3. Create conversion record
  4. Update stockLevel for fromItemId/locationId (deduct fromQty)
  5. Update stockLevel for toItemId/locationId (add toQty)
  6. Update Item.stock for fromItemId (-fromQty)
  7. Update Item.stock for toItemId (+toQty)
  8. Create StockMovement for fromItem: type=CONVERSION, qty=-fromQty
  9. Create StockMovement for toItem: type=CONVERSION, qty=+toQty
  10. Commit transaction

### 4. Server Actions — `lib/actions/conversion-actions.ts`
- `getConversions(filters?)`, `getConversionById(id)`, `createConversion(data)`

### 5. API Routes
- `app/api/conversions/route.ts` — GET (list with filters) + POST (create)
- `app/api/conversions/[id]/route.ts` — GET (single)
- `app/api/conversions/stock-level/route.ts` — GET (stock level by item+location)

### 6. Page — `app/(dashboard)/conversions/page.tsx`
- Follow adjustments page pattern but NO delete functionality
- States: conversions[], viewItem, formOpen, loading, appTimezone, activeFilters
- Only: getConversions, createConversion (no delete)

### 7. Data Table Components
- `components/data-table/conversion-data-table.tsx` — Desktop table + mobile card view
- `components/data-table/conversion-data-table-columns.tsx` — Columns: Code, Date, Location, From Item, To Item, From Qty, To Qty, Remarks
- `components/data-table/conversion-data-table-toolbar.tsx` — Search + "Add Conversion" button (no delete/export)

### 8. Modals
- `components/modals/conversion-form-modal.tsx`:
  - Fields: Date Converted, Location (select), From Item (select), To Item (select), From Qty, To Qty, Remarks
  - Shows "Current Stock Level" for fromItem when location+fromItem selected
  - Shows "Current Stock Level" for toItem when location+toItem selected
  - Validates fromQty <= available stock (shows error if insufficient)
  - Validates fromItem !== toItem
- `components/modals/conversion-view-modal.tsx`:
  - Shows all conversion fields + from/to item details + audit fields
