# Fix: Timezone Conversion for MongoDB Queries

## Problem

The timezone utility functions `startOfDayInTimezone` and `endOfDayInTimezone` in `lib/utils/timezone.ts` produce incorrect UTC dates when deployed to a server with a different timezone than the app's configured timezone.

**Deployment scenario:**
- Local machine: Pacific/Port_Moresby (UTC+10) — works by coincidence (server tz = app tz)
- Vercel deployment: UTC server — **broken** (server tz ≠ app tz)
- MongoDB Atlas: stores dates in UTC

**What happens on Vercel (UTC server) with app timezone Pacific/Port_Moresby (UTC+10):**

For `startOfDayInTimezone(2026-07-28, "Pacific/Port_Moresby")`:
- Buggy (Vercel): `2026-07-28T00:00:00Z` (midnight UTC — wrong)
- Correct: `2026-07-27T14:00:00Z` (midnight Port Moresby = 2PM previous day UTC)

**Root cause**: `new Date(dayStr + "T00:00:00")` is parsed as server-local time. On a UTC server, this becomes midnight UTC instead of midnight in the app's timezone.

## Fix

### File: `lib/utils/timezone.ts`

Replace the current implementation with `fromZonedTime` from `date-fns-tz` (already installed as dependency):

```typescript
import { formatInTimeZone as tzFormat, fromZonedTime } from "date-fns-tz";

const DEFAULT_TZ = "UTC";

export function formatInAppTimezone(
  date: Date | string,
  formatStr: string,
  timezone?: string | null,
): string {
  return tzFormat(date, timezone || DEFAULT_TZ, formatStr);
}

export function startOfDayInTimezone(
  date: Date,
  timezone?: string | null,
): Date {
  const tz = timezone || DEFAULT_TZ;
  const dayStr = tzFormat(date, tz, "yyyy-MM-dd");
  return fromZonedTime(`${dayStr}T00:00:00`, tz);
}

export function endOfDayInTimezone(
  date: Date,
  timezone?: string | null,
): Date {
  const tz = timezone || DEFAULT_TZ;
  const dayStr = tzFormat(date, tz, "yyyy-MM-dd");
  return fromZonedTime(`${dayStr}T23:59:59`, tz);
}
```

`fromZonedTime` correctly interprets the datetime string as being in the specified timezone and returns a UTC Date object.

## Secondary Fix: `$or` Overwrite Bug in ticket-service.ts

In `lib/services/ticket-service.ts:629-644`, if both `default_view` and `search` filters are set, the `search` filter's `$or` overwrites the `default_view`'s `$or`, losing the "today's tickets" criteria.

**Fix**: Combine both `$or` conditions using `$and`:

```typescript
if (filters?.default_view) {
  const now = new Date();
  const defaultOr = [
    { status: { $in: ["Open", "In Progress"] } },
    { created_at: { $gte: startOfDayInTimezone(now, tz), $lte: endOfDayInTimezone(now, tz) } },
  ];
  
  if (filters?.search) {
    const searchOr = [
      { ticket_no: { $regex: filters.search, $options: "i" } },
      { title: { $regex: filters.search, $options: "i" } },
      { name: { $regex: filters.search, $options: "i" } },
      { email: { $regex: filters.search, $options: "i" } },
    ];
    query.$and = [{ $or: defaultOr }, { $or: searchOr }];
  } else {
    query.$or = defaultOr;
  }
} else if (filters?.search) {
  query.$or = [
    { ticket_no: { $regex: filters.search, $options: "i" } },
    { title: { $regex: filters.search, $options: "i" } },
    { name: { $regex: filters.search, $options: "i" } },
    { email: { $regex: filters.search, $options: "i" } },
  ];
}
```

## Safety

The fix is safe for all timezone configurations:

| Timezone | Start of Day (UTC) | End of Day (UTC) |
|----------|-------------------|------------------|
| UTC (default/null) | `2026-07-28T00:00:00Z` | `2026-07-28T23:59:59Z` |
| Asia/Manila (+8) | `2026-07-27T16:00:00Z` | `2026-07-28T15:59:59Z` |
| America/New_York (-4) | `2026-07-28T04:00:00Z` | `2026-07-29T03:59:59Z` |

- When timezone is UTC or not set: output is identical to current behavior (no regression)
- When timezone is non-UTC: now correctly converts to UTC (was previously wrong)
- `fromZonedTime` is from the same `date-fns-tz` library already in use
