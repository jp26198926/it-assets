# Fix Timezone Handling in /ticket-report Page

## Problem

The `/ticket-report` page computes its default 30-day date range using `new Date().toISOString().split("T")[0]`, which always produces **UTC dates**. This is incorrect — the date range should respect the app's configured timezone (e.g., `Asia/Manila`).

**Example bug:** If it's `11 PM in Manila (UTC+8)` on Jul 28, `toISOString()` returns `2026-07-29T15:00:00.000Z`, so the default "to" date becomes **Jul 29** in UTC, while the server-side date filter (which correctly uses `endOfDayInTimezone`) would filter up to Jul 28 23:59:59 Manila time. This mismatch can cause off-by-one-day results.

The `/tickets` page doesn't have this issue because it doesn't use a UTC-based default date range.

## Files to Modify

| File | Change |
|------|--------|
| `lib/utils/timezone.ts` | Add `getDateInTimezone()` helper that returns `yyyy-MM-dd` string in a given timezone |
| `app/(dashboard)/ticket-report/page.tsx` | Fetch timezone first, then compute default date range using the timezone |
| `components/reports/date-range-filter.tsx` | Accept optional `timezone` prop and use it for the default date range computation |

## Changes

### 1. `lib/utils/timezone.ts` — Add helper

Add a new exported function:

```ts
export function getDateInTimezone(
  date: Date,
  timezone?: string | null,
): string {
  return tzFormat(date, timezone || DEFAULT_TZ, "yyyy-MM-dd");
}
```

This returns the date string (e.g., `"2026-07-28"`) as it appears in the target timezone.

### 2. `app/(dashboard)/ticket-report/page.tsx` — Fetch timezone before computing defaults

**Current flow:**
1. `getDefaultDateRange()` runs at module init (UTC-based)
2. `useEffect` fetches app settings → sets `appTimezone`
3. Default dates are already wrong by the time timezone arrives

**New flow:**
1. Remove the `getDefaultDateRange()` call at module init
2. Initialize `filters` as `null` (or with empty dates)
3. In the `useEffect`, fetch both `getAppSettings()` and data together
4. Compute the timezone-aware default range after timezone is known
5. Set both `appTimezone` and initial `filters` from the effect

```tsx
// Before: const defaults = getDefaultDateRange();  // UTC-based
// After: Initialize with null dates, compute in useEffect

const [filters, setFilters] = useState<TicketReportFilters>({
  date_from: null,
  date_to: null,
});

useEffect(() => {
  getAppSettings().then((s) => {
    setAppTimezone(s.timezone);
    // Compute timezone-aware defaults
    const tz = s.timezone;
    const to = getDateInTimezone(new Date(), tz);
    const now = new Date();
    now.setDate(now.getDate() - 30);
    const from = getDateInTimezone(now, tz);
    const defaults = { from, to };
    setFilters(defaults);
    fetchData(defaults);  // Auto-fetch on mount
  }).catch(() => {});
}, []);
```

### 3. `components/reports/date-range-filter.tsx` — Accept timezone prop

**Current:** `getDefaultDateRange()` is a local function using UTC.

**New:**
- Add optional `timezone?: string | null` to `DateRangeFilterProps`
- Import `getDateInTimezone` from `@/lib/utils/timezone`
- Replace the local `getDefaultDateRange()` with a timezone-aware version:

```tsx
interface DateRangeFilterProps {
  filters: TicketReportFilters;
  onFiltersChange: (filters: TicketReportFilters) => void;
  onApply: (filters: TicketReportFilters) => void;
  timezone?: string | null;
}

function getDefaultDateRange(timezone?: string | null) {
  const to = new Date();
  const from = new Date();
  from.setDate(from.getDate() - 30);
  return {
    from: getDateInTimezone(from, timezone),
    to: getDateInTimezone(to, timezone),
  };
}
```

Then in the component:
```tsx
export function DateRangeFilter({ filters, onFiltersChange, onApply, timezone }: DateRangeFilterProps) {
  const defaults = getDefaultDateRange(timezone);
  // ... rest unchanged
}
```

And in `page.tsx`, pass the timezone:
```tsx
<DateRangeFilter
  filters={filters}
  onFiltersChange={setFilters}
  onApply={(f) => fetchData(f)}
  timezone={appTimezone}
/>
```

## What's Already Correct (No Changes Needed)

- **Server-side** (`ticket-report-service.ts`): `buildDateFilter` already uses `startOfDayInTimezone`/`endOfDayInTimezone` with the app timezone. MongoDB `$dateToString` aggregation also uses the timezone. ✅
- **TicketListTab**: Already receives and uses `timezone` for `formatInAppTimezone`. ✅
- **Summary/Totals/Category tabs**: These don't display raw dates (labels come from server-side aggregation in the correct timezone). No changes needed. ✅
