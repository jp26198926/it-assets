# Plan: Add Asset Selector to Edit Ticket Modal

## Goal
Allow users to change/select the associated asset in the Edit Ticket modal.

## Key Findings
- `UpdateTicketInput` already supports `asset_id?: string` (`lib/types/ticket.ts:47`)
- `getTicketSelectOptions()` already returns `assets: { id, barcode, itemName }[]` (`lib/services/ticket-service.ts:1044-1077`)
- The service query at line 1060 already fetches active assets: `AssetModel.find({ deleted_at: null, status: { $ne: "Repair" } })`
- The page currently ignores `options.assets` when setting `selectOptions` (line 165-169)
- The modal has no `asset_id` field and its `onConfirm` signature doesn't include it

## Files to Modify

### 1. `components/modals/ticket-edit-modal.tsx`
- Add `assets: { id: string; barcode: string; itemName: string }[]` to `selectOptions` prop type
- Add `asset_id: string` to the `onConfirm` data type
- Add `assetId` state + `useEffect` initialization from `ticket.asset_id || ""`
- Add an "Asset (Optional)" Select field (with "None" option) between Department and Priority
- Include `asset_id` in the `onConfirm` call

### 2. `app/(dashboard)/tickets/[id]/page.tsx`
- Add `assets` to the `selectOptions` state type definition
- Pass `assets: options.assets || []` when calling `setSelectOptions`
- Add `asset_id: string` to the `handleEditConfirm` parameter type
- Pass `asset_id: data.asset_id || undefined` to `updateTicket`

## Verification
- Open a ticket detail page, click Edit
- Confirm the Asset dropdown appears with assets listed and "None" option
- Confirm the currently linked asset is pre-selected
- Change the asset, save, and verify it updates
- Verify "None" unlinks the asset
