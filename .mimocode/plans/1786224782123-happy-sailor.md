# Adjustment Module Implementation Plan

## Overview
Create a new "Adjustment" entity for stock adjustments. This is a ledger-type module — no action buttons in the datatable. Users reverse entries by adding records with negative quantities. All saves are transactional (update StockLevel + Item.stock + create StockMovement).

## New Files to Create

### Step 1: Types

- `Adjustment` interface: `id`, `code`, `date_adjusted`, `location_id`/`location_name`, `item_id`/`item_name`/`item_code`, `qty`, `remarks`, + full audit fields (created_at/by, updated_at/by, deleted_at/by/reason)

- `AdjustmentFilters`: `search?`, `code?`, `location_id?`, `item_id?`, `date_from?`, `date_to?`

### Step 2: Mongoose Model
**`lib/db/models/adjustment.ts`**
- Schema fields: `code` (unique), `date_adjusted` (Date, required), `location_id` (ref: "Location", required), `item_id` (ref: "Item", required), `qty` (Number, required), `remarks` (String, nullable), + `...BaseAuditSchemaDefinition`
- Indexes: `code` (unique), `location_id`, `item_id`, `date_adjusted` (desc)
- Collection: `"adjustments"`
- Singleton pattern: `mongoose.models.Adjustment || mongoose.model(...)` 

### Step 3: Service Layer
**`lib/services/adjustment-service.ts`**

Functions:
- `generateAdjustmentCode()` — query last code matching `^ADJ\d{5}$`, increment, return `ADJ00001` format
- `toAdjustment(d)` — mapper handling populated refs (same pattern as `toReceiving`)
- `applyPopulates(query)` — populate location_id (name), item_id (name item_code), created_by/updated_by/deleted_by (first_name last_name)
- `getAdjustments(filters?)` — list with search, code, location_id, item_id, date_from, date_to filters; sort `created_at: -1`
- `getAdjustmentById(id)` — single lookup with full population
- `getStockLevelForItemAndLocation(itemId, locationId)` — returns `{ qty: number } | null` from StockLevel collection
- **`createAdjustment(data)` — TRANSACTIONAL:**
  ```
  session = startSession()
  session.startTransaction()
  try:
    1. Generate code (ADJ00001)
    2. Create Adjustment record
    3. Find or create StockLevel for (item_id, location_id)
    4. $inc StockLevel.qty by adjustment.qty
    5. $inc Item.stock by adjustment.qty
    6. Create StockMovement:
       { date: now, transaction_type: "ADJUSTMENT",
         item_id, location_id, qty: adjustment.qty,
         reference_trans_id: adjustment._id,
         reference_item_id: null,
         reference_description: adjustment.code }
    7. Commit transaction
    8. Return populated adjustment
  catch: abort transaction, throw
  finally: endSession()
  ```
- `deleteAdjustment(id, reason?)` — soft-delete: set deleted_at, deleted_reason, status, updated_at

### Step 4: Server Actions
**`lib/actions/adjustment-actions.ts`**
- `"use server"` wrappers: `getAdjustments`, `getAdjustmentById`, `createAdjustment`, `deleteAdjustment`
- Inject auth user for created_by/updated_by via `getAuthFromRequest()`

### Step 5: API Routes
**`app/api/adjustments/route.ts`** — GET (list with filters from searchParams) + POST (create, validate date_adjusted/location_id/item_id/qty)
**`app/api/adjustments/[id]/route.ts`** — GET (single) + DELETE (soft-delete with reason)
**`app/api/adjustments/stock-level/route.ts`** — GET: accepts `location_id` and `item_id` query params, returns `{ qty: number } | null`

Auth: `withPageAuth("/adjustments", "Access"|"Add"|"Delete")` per route

### Step 6: Frontend Page
**`app/(dashboard)/adjustments/page.tsx`**
- State: `adjustments[]`, `formOpen`, `viewItem`, `loading`, `appTimezone`, `activeFilters`
- NO `editItem` or `deleteItemItem` state (no edit/delete actions)
- `handleAdd` → opens form modal
- `handleView` → sets viewItem → opens view modal
- Load adjustments on mount via `getAdjustments()`

### Step 7: Data Table Components
**`components/data-table/adjustment-data-table.tsx`**
- Same structure as stock-movement-data-table (read-only, no CRUD action buttons)
- Desktop table + mobile card view
- Props: `columns`, `data`, `onView`, `onAdd`, `onServerSearch`, `onServerSearchClear`
- Includes `<DataTablePagination>` and `<AdjustmentDataTableToolbar>`

**`components/data-table/adjustment-data-table-columns.tsx`**
- Factory function: `createAdjustmentColumns(handleView, appTimezone)`
- Columns: Code, Date Adjusted (formatted), Location, Item (code + name), Qty (colored: green positive, red negative), Remarks
- NO actions dropdown column

**`components/data-table/adjustment-data-table-toolbar.tsx`**
- Search input with server-side search
- Add Adjustment button (permission-gated)

### Step 8: Form Modal
**`components/modals/adjustment-form-modal.tsx`**

Special behavior:
1. On open: load Location and Item select options
2. When BOTH location_id and item_id selected: call `GET /api/adjustments/stock-level?location_id=X&item_id=Y` → display "Current Stock: X units"
3. When qty input changes: display "Projected Stock: {currentStock + qty}" with visual indicator if negative
4. Fields: date_adjusted (date, default today), location_id (Select), item_id (Select), qty (number input, allows negative), remarks (textarea)
5. Validation: date_adjusted required, location_id required, item_id required, qty required
6. Submit: call createAdjustment action

Structure follows scrollable modal pattern (DialogContent flex-col max-h-[85vh], DialogHeader pinned, form flex-1 overflow-y-auto, DialogFooter pinned outside form)

### Step 9: View Modal
**`components/modals/adjustment-view-modal.tsx`**
- Display: Code, Date Adjusted, Location, Item, Qty (colored), Remarks
- Audit fields section (per AGENTS.md standard): Created At, Created By, Last Updated, Updated By
- Conditional deleted fields (Deleted At, Delete Reason, Deleted By) with `text-rose-600`
