# Fix public `/support/submit` empty dropdowns & barcode lookup

## Diagnosis

**Root cause: `proxy.ts` whitelist gap — not missing routes.**

The public support pages already call purpose-built public APIs under `app/api/public/tickets/*`, and those routes already run with **no** `withPageAuth`. But `proxy.ts` (Next.js 16's middleware) only exempts `/api/auth/*` for APIs — `/api/public/*` is **not** whitelisted, so every anonymous fetch gets `401 { success: false, error: "Unauthorized" }` **before the route handler runs**.

The page then swallows that failure and shows it as other symptoms:

| Fetch | Route (already exists) | Proxy | Symptom on page |
|---|---|---|---|
| `GET /api/public/tickets/select-options` | `app/api/public/tickets/select-options/route.ts` | 401 | Empty category + department dropdowns |
| `GET /api/public/tickets/lookup-asset?barcode=` | `app/api/public/tickets/lookup-asset/route.ts` | 401 | "Asset not found for this barcode" |
| `POST /api/public/tickets` | `app/api/public/tickets/route.ts` | 401 | Submit fails |
| `GET /api/public/tickets/track` | `app/api/public/tickets/track/route.ts` | 401 | Track page also broken |
| `GET /api/cloudinary` | `app/api/cloudinary/route.ts` | 401 **and** `withPageAuth` | max_file_size falls back to 10 silently |
| `POST /api/tickets/upload` | `app/api/tickets/upload/route.ts` | 401 | Attachments + rich-text images fail |

**Two secondary gaps** (still broken after the proxy fix):

1. `GET /api/cloudinary` is RBAC-gated and returns **secrets** (`api_key`, `api_secret`) — must not be opened to the public. The submit page only needs `max_file_size`.
2. `POST /api/tickets/upload` has **no handler auth** and is shared with the dashboard (`ticket-form-modal.tsx`, `tickets/[id]/page.tsx`). It should stay behind auth for staff; the public form needs its own upload route.

## Approach

**No new "category/department/barcode" routes needed** — they exist. Fix the proxy whitelist, then close the two secondary gaps (safe config + public upload).

### 1. Whitelist `/api/public/` in `proxy.ts`

**File:** `proxy.ts`

Extend the existing API exemption (line 21) to also allow `/api/public/`:

```ts
if (pathname.startsWith("/api/auth/") || pathname.startsWith("/api/public/")) {
  return NextResponse.next();
}
```

This single change unblocks select-options, lookup-asset, create ticket, and track.

Do **not** change the `/support*` page branch — the "logged-in users bounce to /dashboard" behavior is intentional.

### 2. Expose `max_file_size` safely via select-options

**File:** `app/api/public/tickets/select-options/route.ts`

- Also read Cloudinary settings (`getCloudinarySettings()`) and include **only** `max_file_size` in the response data (never `cloud_name` / `api_key` / `api_secret`).
- Switch raw `NextResponse.json` to `apiSuccess()` / `apiError()` from `@/lib/services/api-helpers` (project rule).
- Response shape becomes:
  ```ts
  { categories: [...], departments: [...], max_file_size: number }
  ```

**File:** `app/(public)/support/submit/page.tsx`

- Remove the separate `fetch("/api/cloudinary")` call (lines 89–94).
- Read `max_file_size` from the select-options response into existing `maxFileSize` state (default 10 remains as fallback).

### 3. Public ticket upload route

**New file:** `app/api/public/tickets/upload/route.ts`

- Same behavior as `app/api/tickets/upload/route.ts` (Cloudinary upload to `it-assets/tickets`, `max_file_size` check, sanitized filename, returns `{ success, url }`).
- No `withPageAuth` — intentionally public (reachable only via `/api/public/` after step 1).
- Prefer extracting the shared upload body into a helper (e.g. `uploadTicketAttachment(file, fileName)` in `lib/services/cloudinary-service.ts` or a small `lib/services/ticket-upload-service.ts`) and have **both** the public route and the existing `app/api/tickets/upload/route.ts` call it — avoids duplicated Cloudinary logic.

**File:** `app/(public)/support/submit/page.tsx`

- Point `uploadFile()` and the rich-text image upload at `/api/public/tickets/upload` instead of `/api/tickets/upload`.

Leave `app/api/tickets/upload/route.ts` in place for dashboard callers (`ticket-form-modal.tsx`, `tickets/[id]/page.tsx`); it stays proxy-protected (auth cookie required).

### 4. Surface fetch failures on the submit page (small UX fix)

**File:** `app/(public)/support/submit/page.tsx`

- In the select-options `useEffect`, when `res.success` is falsy, `toast.error(res.error || "Failed to load form options")` instead of silently leaving dropdowns empty.
- In `handleBarcodeLookup`, distinguish "not found" (404 / `!data.data`) from request failure (401/500) so users don't see a misleading "Asset not found" when the real problem is auth/network.

## Files to change

| File | Change |
|---|---|
| `proxy.ts` | Whitelist `/api/public/` alongside `/api/auth/` |
| `app/api/public/tickets/select-options/route.ts` | Add `max_file_size` (safe fields only); use `apiSuccess`/`apiError` |
| `app/api/public/tickets/upload/route.ts` | **New** — public upload endpoint |
| `lib/services/cloudinary-service.ts` (or new `ticket-upload-service.ts`) | Extract shared upload helper |
| `app/api/tickets/upload/route.ts` | Call shared helper (keep auth-via-proxy) |
| `app/(public)/support/submit/page.tsx` | Use new endpoints; drop `/api/cloudinary` call; better error toasts |

## Out of scope (pre-existing, note only)

- `/api/cloudinary` GET returns `api_secret` to authorized staff — existing behavior, not part of this bug.
- Public page uses basic `Select` instead of `SearchableSelect` (project rule) — pre-existing divergence; optional polish, not required to fix the bug.
- Rate-limiting / abuse protection on the public upload endpoint — worth a follow-up if the form is exposed to the internet.
